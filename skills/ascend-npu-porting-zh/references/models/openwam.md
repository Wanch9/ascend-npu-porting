# OpenWAM-α：MS-HAB 训练与扩展

## 范围与来源

来源：项目 `OpenWAM-NPU/NPU_PORTING.md` 及已保存的 `artifacts/npu_formal/latest-status.json` 快照；摘要见 [sources.json](sources.json)。报告覆盖 2026-10-14 至 10-25。本页依据已有记录整理，不代表实时查询了训练服务。

源码基线 `4d7f642b841913ea3c176010b692b1de3d5ef180`；官方 α 权重 revision `52df4e66c82c5c8b480adcc8d01f4db7415dfb56`、step154000。MS-HAB 五任务接口为 state12/action13、32 步动作及 9 帧视频。只重新初始化动作输入、动作输出、状态输入三处接口；VAE/T5 冻结，基线视频/动作 DiT 以 BF16、ZeRO-2 训练。

## 可复用经验

- 明确机器人动作语义，关节/底盘控制不能冒充末端位姿。非替换张量严格匹配 keys/shapes，新接口跨 rank 同种子初始化；继续训练时关闭接口重置。
- 使用 α 原生 512-token T5 条件，不复用旧 FastWAM 的 128-token 文本缓存。视频/文本精度对照与任务效果分别验证。
- RoPE 频率在 CPU 构造，NPU 使用经过对照的 FP32 实数旋转；探针与训练的数值配置保持一致。
- 保存 Python/NumPy/CPU/NPU RNG 与确定性 sampler 进度；检查后续轮次中途恢复，不只测试轮次边界。
- ZeRO 恢复验证器曾漏算末尾三个 padding 值；先检查分片语义，再判断保存是否损坏。分别比较“加载完成的状态”和“下一次反向/更新后的结果”。
- 分析框架开销：DeepSpeed 0.18.5 ZeRO-2 钩子反复遍历 1,651 个参数和 autograd 节点。项目内按 backward graph task 缓存，并检查参数身份及 requires-grad；有界对照的 26,416 次调用与原路径一致。该优化依赖所测版本及同一图内参数契约。
- 测量真实 DataLoader 和目标拓扑。冻结 Wan 参数但保留联合注意力时仍可能需要视频计算梯度；改为 cross-attention/no-grad 属于架构实验，不能当作数值等价加速。

## 证据与边界

八卡真实更新、保存、新进程恢复并再更新均退出 0；恢复时 FP32 主权重、Adam 动量及步数抽检与保存值相同。但逐位续训检查失败：两次恢复分别有 96/95 个参数抽样值不同（共 206,848 个），最大分支相对 RMS 差异约 0.0103%/0.0080%，尽管输入/loss 相同。具体算子未定位，其他模型的确定性 HCCL 结论不能替本案例宣告修复。

已保存的正式作业快照记录完成 30,000 次更新，训练与备份退出码均为 0。该长训只保存推理权重，不能据此证明其完整状态恢复或策略成功率。

10 月 25 日双节点（8×910B1 + 8×910B2）、global batch256 短测为 3.587 秒/更新；冻结 Wan 联合注意力及 cross-attention/no-grad 两种实验分别为 3.248、2.863 秒/更新，后者增加约 4.76 亿动作侧参数。三者契约不同，不能宣称任务效果等价或设为新模型默认配置。
